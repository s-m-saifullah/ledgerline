- **2026-10-31:** Web redesign, PR 9 of [ADR 0047](adr/0047-web-redesign.md): the **`paidThisMonth` API change** (server only; API 0.1.51, no migration; merged as #212). Every client from `GET /contacts` and `GET /contacts/{id}` (and the write responses that return one) carries `paidThisMonth: { base, amounts }`: what its payments settled in the month, per service currency, and its worth in USD from the base value saved on each payment entry (so a later rate change never moves an old month and no currency is left out). A payment counts in the month of its entry's date; deleted payments and tips do not. Both reads take an optional `month` (`YYYY-MM`, 400 when invalid); without it the figure covers the current month in the ledger's time zone (UTC when none is set). The list does one grouped query. OpenAPI regenerated, `docs/api-changes.md` 0.1.51 written, the Android `Contact` carries a `PaidThisMonth` and its contract tests check it (the phone does not show it). New: `paid-this-month.test.ts` (month edges, two currencies and a later rate change, a deleted and a moved payment, tips, the time zone default with a fixed clock, `month` validation, and a second ledger's payments never counted, through the API and at the query itself). 17 deliberate mutations; 3 first slipped through (a mutation aimed at the wrong line, a month check that today's date satisfied by chance, a ledger filter hidden behind the client keying, now tested on the query), each now caught. Counts: web 832, ui 50, api 566, shared 98. It reaches production with the next server release, which the owner tags.
