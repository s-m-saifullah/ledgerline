- **2026-11-13:** Security: **sign-in limits follow each visitor, not the proxy** (merged as #275; not released: it ships with the next server tag, which carries the new web image; no migration, API contract unchanged). **The problem:** the API limits sign-ins per client address (three tries in ten seconds), reading it from `X-Forwarded-For`. The web container's Caddy did not trust the host proxy in front of it, so it replaced the header with the proxy's own Docker address and every visitor shared one limit: one stranger sending a bad sign-in every few seconds could have kept the household out. The owner read the stored session addresses on the server (one private address), which confirmed it. **The fix:** the web container's `Caddyfile` trusts private peers only (strict, so the chain is read from the right) and hands the API the one client address it worked out; a header a visitor makes up is ignored, and a visitor on a private address shares the proxy's limit with other such visitors. No Better Auth setting changed: it already accepts a single-address header, and a `trustedProxies` list would have made it ignore clients on private addresses. `docs/SELF_HOSTING.md` says the host proxy must pass each visitor's address (Caddy does by itself; nginx needs one line). **Proof:** on a scratch stack of two proxies and the real API, bad sign-ins from two client addresses: with the old `Caddyfile` the second client was refused on its first try, with the new one it was not. **Tests:** four new tests against the real Caddy image and `Caddyfile` with a stub upstream (three failed first), and three API tests that pin the other half of the contract (the per-client limit, IPv6 grouped by /64, a chain of addresses falling into one shared limit; they passed from the start because the API side was already right); 10 deliberate mutations, all caught; the infra suite passes (15 skip without `flock`). The first CI run failed in the public audit, which refuses private-address literals in tests; the tests now use the real peer address and documentation addresses. **Not changed:** the two-factor guess cap the review suspected is missing exists already (Better Auth caps attempts per challenge and locks an account for 15 minutes after ten failures; `two-factor.test.ts` proves it). A database lookup in `isSignInStopped` still runs before the sign-in limiter. **Also merged:** Dependabot's npm group (#273: `better-auth` 1.7.19, `vite` 8.3.7, `@testing-library/user-event` 14.6.9) and Gradle group (#269: Roborazzi 1.78.0), both green; the npm bumps ship with the next server tag.
