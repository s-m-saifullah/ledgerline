- **2026-11-10:** A flaky Android sign-in test fixed (test only; no app change; in review as #250). `SignInViewModelTest.theAccountIsAskedAboutWithTheNewTokenBeforeTheSessionHasIt` (slice 2 of [ADR 0050](adr/0050-money-writes-on-the-phone.md)) failed once on a pull request's check and passed on a rerun of the same commit. **Cause:** the session enters its offer state on the network thread while the view model is still running there, so the test's watcher of session states is resumed after the screen has finished, and the test thread could compare its list first (a slow runner makes that likely). **Reproduced** by making the watcher slow (300 ms): the old test failed every time. **Fix:** the watcher keeps its states in a list that is safe to read from another thread, and the test waits for the states it expects before comparing; the check that the session never offered a token now waits for the first state and pauses 300 ms before saying none came. With the slow watcher the test passes, and it passed three normal runs; nothing in the app changed.
