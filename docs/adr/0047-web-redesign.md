# ADR 0047: Web redesign, one design language with the phone

Date: 2026-10-28. Status: accepted by the owner in chat, after reviewing and correcting an interactive prototype (the owner answered the open choices and asked for this ADR and its plan to be recorded). Amends [0045](0045-one-design-for-web-and-android.md) and [0046](0046-clutter-free-redesign.md) for the web, and the design rules in [CLAUDE.md](../../CLAUDE.md). Builds on [0039](0039-interactive-control-styles.md), [0040](0040-accessibility-pass.md), [0041](0041-pwa.md) and [0044](0044-live-updates-in-the-web-app.md).

## Context

The phone redesign is finished and released ([0046](0046-clutter-free-redesign.md), `android-v0.2.0`). ADR 0046 suspended the rule that the web is the reference and said the web follows with its own plan. The web still has the older look: eyebrows and subtitles on most pages, long hint paragraphs, a breadcrumb in the top bar, a different button and card style, filters behind a disclosure, five icon buttons on every category row, an action bar on every service, a Status select where the phone has a Pending switch, and a layout that switches at one width (700 px) in CSS and again in JavaScript (`useIsPhone`), so Categories, Clients and Loans render different markup on a phone.

There was no prototype to follow, so one was built and reviewed: an interactive page with synthetic data only (kept locally, not in the repository) showing every screen at phone, tablet and desktop widths in light and dark. A read-only inventory of the web app (about 700 pages, dialogs, actions, settings and shortcuts, and the Playwright specs that pin them) was made first, and every item must survive: it is ticked off in each pull request.

## Decisions

### Same design language as the phone

- **Tokens, type, shape.** `packages/ui/src/tokens.css` stays the one source: teal accent from one seed (OKLCH), zinc surfaces, red only for overspending, errors and Delete, the deep accent for the hero, the chart ramp as tints of the accent. The type scale of 0046 applies on every width: 10 px floor, 12 secondary, 14 body, 19 titles, 27 page titles, 31 amounts, 35 hero amount, Inter. Shapes: 12 px fields and buttons, 16 px cards, 20 px hero, 24 px sheets and drawers (the web's 8, 12 and 16 are replaced). Borders, never shadows. Touch targets stay at 44 px (the web's rule; the phone's 48 dp is Android's).
- **Same pieces, named alike:** top bar, segmented control, grouped list card and row (avatar or tile, title, at most one short hint, trailing value), status pill, proportion bar, filter chip, section label, empty state, hero, month control, switch row, and one overlay component (below). They live in `packages/ui` or `apps/web/src/components` (shared between features, per `CONTRIBUTING.md`), and the old classes are removed as each screen moves.
- **Few words, every screen.** No eyebrows, page subtitles, breadcrumbs, scope labels ("This device") or repeated labels. A hint is one line. Long help paragraphs in forms become one sentence or leave. The privacy hint that said "Blurs" while the app removes the digits is corrected.
- **Same words for the same things** (In hand, Clients, Loans, Pending), with the two deliberate differences below.

### Shell and layout (direction B, "workspace")

- **Phone (under 700 px).** A fixed top bar (page title 19 px, a back arrow on pages opened from More, the privacy switch, the theme switch), five tabs (Home, Transactions, Budgets, Insights, More) and **one Add button, bottom right, above the bar, that follows the screen**: a transaction on Home, Transactions, Budgets and Insights; an account on Accounts, a category on Categories, a tag on Tags, a currency on Currencies, a rule on Recurring, a client on Clients (a service on a client's own page), Lend or borrow on Loans. There is none on More, Settings and Import and export. The plus in the header of those screens goes. Its accessible name says what it adds ("Add account"), so specs that tap Add on a phone from one of those pages change on purpose.
- **Tablet (700 to 1099 px).** A left icon rail (88 px, labels at 10 px) with Add (a transaction) at the top and the jump-to search button at the bottom. A thin top bar of global tools only: sync status, privacy, theme.
- **Desktop (1100 px and up).** A 248 px sidebar: brand, Add (a transaction), the five destinations, then More's pages under three group labels (Receivables and lending: Clients, Loans; Money setup: Accounts, Categories, Tags, Currencies, Recurring; Data and preferences: Import and export, Settings), the jump-to button (Cmd/Ctrl+K) and the signed-in owner with Sign out. The More link is hidden there; More stays the page on phone and tablet (grouped rows with live figures: clients owed, people owed, category counts, the version).
- **Top bar tools.** The breadcrumb ("Personal ledger > Page") goes. A **sync status** is new on the web: Synced, Updating or Offline, from the live-updates poller of 0044 (it shows nothing today). The theme control in the header **switches light and dark in one click**; System is chosen in Settings (a segmented control: Light, Dark, System). The privacy switch stays. The header search button is not repeated: the palette opens from the sidebar button or Cmd/Ctrl+K. A phone has no palette button (hardware keyboard only, as today); adding one is a later decision.
- **One layout system.** Two container widths (700 and 1100 px) drive the layout in CSS. The JavaScript `useIsPhone` branches that render different markup (Categories, Clients, Loans, action bars, dialog delete buttons) go, so the phone and desktop differ in layout, not in which controls exist.
- **Using the width, not stretching the phone.** Pages are at most 1160 px; simple list pages (Tags, Recurring, Currencies, and lists in the plain direction) are capped near 760 px. Home is two bands (the hero beside This month, then accounts beside Latest transactions) so every column starts on one line; at tablet width accounts are one column. Transactions rows gain Tags and Account columns on desktop instead of a longer hint. Budgets puts the hero beside the list (5 to 7). Insights lays the category card beside the charts. Categories shows Expense and Income side by side from tablet width (no segmented control). Accounts and the More page use two columns. **Clients and Loans are a list beside the open client or person from 1100 px**, and each client and person gets its own address (`/clients/:id`, `/loans/:id`) so Back and reload work (today the selection is local state and there is no deep link); below 1100 px they are pages with a back link.
- **Overlays.** A bottom sheet on a phone, a right-hand drawer (440 px, 560 px for wide forms) from 700 px, a centred dialog for questions (delete, archive, write off, sign out others). One sheet pattern: Cancel, a title, an optional action, content, one primary button pinned at the bottom; an editor's first delete step is a trash icon beside Save (replacing `DialogDeleteButton`), asking before it deletes. Pickers (account, category, tags) open inside the same sheet with a search box from eight choices at a fixed height, and "New category" pinned under the list. Focus, Escape, the Radix dialog behaviour and the interrupted-save recovery (Retry with the same Idempotency-Key, Reload latest details, Resume action) are kept as they are.

### Screens

- **Home.** The In hand hero with up to three small figures; This month (in, out, net with a bar; opens Insights); accounts in Cash and banking and Cards and loans (cards and loans are listed, not folded into "N other accounts"), a currency control only with two or more currencies; **Latest transactions stays** (the phone has none; it is the web's right-hand column on a desktop and follows the accounts on a phone); the pending note becomes a link to the pending entries; the first-run states (Set up accounts, Set up categories) stay. The page keeps its h1 "Home".
- **Transactions.** Search with a Filters button (count), kind chips (All, Expenses, Income, Transfers), day cards with the day's net and a plus sign on income and a day that came out ahead, a transfer's two legs as one row "From → To" (same-day payees are not merged), Pending as a marker. Filters (account, category, tag, dates, status: All, Cleared, Pending) open in the sheet or drawer and stay a draft until Apply, as the URL filters work today; Clear filters, Load more, the invalid range message and the CSV export that follows the filters stay (Export CSV is a page action). The "Filter entries" and "Import and export" disclosures go.
- **Editor** (Add, Edit, transfer). A type pill (Expense, Income, Transfer) for a new entry, a large amount with its currency code, one card (payee, account, category, when) and one card (tags, note, **Pending as a switch**, off by default: saved as cleared). A transfer shows From and To with a **swap** button (the web has none today) and keeps fee, bonus and the other-currency fields. Splits, the exchange rate fields, client and loan links, the time, delete with Undo and the unconfirmed-save recovery all stay. A transfer or client-payment row still opens its own editor.
- **Budgets.** Month control, a Left this month hero with a bar (red when over), one list sorted overspent first then by spending, carried over, categories with no budget and no spending folded into one line, Set limit in a sheet with Remove limit and the carry-over switch, Copy from last month in an empty month.
- **Insights.** Summary card (spent, money in, net, share kept), a category card with proportion bars and expandable parents, the 12-month chart only with two or more active months, and **Net worth now** (assets and liabilities from the account balances, left out with more than one currency) beside the net worth over time. **Net worth leaves the Accounts page** (as on the phone). The "Show the figures" tables stay, and the page order (spending, cash flow, net worth) that a spec relies on is kept.
- **Clients.** A total card, search, Open, Settled, All chips, one list sorted by amount owed. A client: a balance card with **Paid in Oct** (new: money received from this client this month), an overdue line with reserved height, contact details, **Record payment from the client** (pays oldest first, with the preview and Pay full balance) and Log service, a menu with Edit client, Archive and Delete; the unpaid services pinned, Paid and History as a segmented control (the prototype shows the same switch on every width). **A service is one row and a tap opens its sheet**: its payments (Edit or Delete each; Edit or Delete receipt for a payment that covered several services), Record payment, **Edit service** (description, dates, time, due date, currency, amount, the hours helper, move to another client), Write off remainder or Reopen service, Delete service. This replaces the action bar and the Show payments toggle on every row. History lines stay as today for now; batching them like the phone is not part of this redesign. Settle, Mark paid and Send reminder (shown by the phone concept) are not built on either app.
- **Loans.** One summary card, the people list, search only from eight people, Active, Archived, All chips only while someone is archived. A person: Record repayment (Lend money when nothing is open) and a menu (Lend money, Borrow money, Waive what is left, Rename, Archive or Unarchive); the balance per currency with Remove, Before Ledgerline with Change, Activity (the latest eight, as today) with a link to every entry in Transactions. The dialogs stay: Add loan (Who, what happened, a new person), lend, borrow, repayment, waive with its category, change the opening balance, rename, archive, and Remove the loan including the version that lists the entries still using it. An archived person shows only Rename and Unarchive (the web shows the others disabled).
- **Categories.** Expense and Income, search, Expand all, one accordion card, the status chips only while something is archived, **one actions sheet** (Edit, Add subcategory, Move up, Move down, Merge into, Archive or Unarchive, Delete in red) instead of five icon buttons per row on desktop and a kebab menu on a phone. The starter set, merge preview and reorder stay.
- **Accounts, Recurring, Tags, Currencies.** Grouped like Home; one editor sheet each; the currency field only with a second currency; the archived view; the interrupted-save recovery. **Tags gets a search field** (new; always shown, since the owner asked for it).
- **Import and export.** One page under More: the four-step import (file, columns, categories, review, then done, with possible duplicates, new tags, recent imports and Undo) and Export (a date range and the transactions, accounts and categories files). Export leaves Settings and the Transactions disclosure; Settings keeps one row that opens this page.
- **Settings.** Grouped sections: Appearance (Light, Dark, System), Privacy and input (Hide amounts, Type amounts from the cents), Ledger (time zone), Your data (opens Import and export), Security (two-factor: set up, new backup codes, turn off), Signed-in devices (sign out one, sign out all others), Sign out in red.
- **Sign-in and two-factor.** One centred card, no marketing half: Welcome back, Email address, Password, Sign in; the code step with Continue, Use a backup code instead, Back to sign in. Titles and the h1 pins stay.

### Where the web and the phone differ on purpose

- **Words for money owed.** The phone adds clients and loans into one "Owed to you". **The web keeps them apart** (the owner's ruling) and names the figures by who owes, so they cannot read as the same thing: **Clients owe**, **People owe**, **You owe**, each with its page's icon and each a link, each shown only when not zero. The Loans summary uses the same words (People owe, You owe), replacing Lent out. The Loans row on More shows the People owe figure.
- **Add** follows the screen on a phone (above); on tablet and desktop it is one Add in the sidebar plus each page's own button ("Add account").
- **Overlays and panes** use the width (drawer, list beside detail); the phone uses sheets and pages.
- **Top bar** holds global tools on wider screens and the title on a phone.
- **Web only, kept:** Latest transactions on Home, time zone, two-factor setup, the devices list, the CSV import wizard, Recurring, Tags, Currencies, category merge and reorder, transfer fee and bonus, split entries, the client hours helper, Undo after deletes.
- **Android only, out of scope:** in-app updates, the lock screen. **Not decided, not built:** Auto-Set Limits, the in-app keypad.

### The one server change

**Paid in Oct** needs a figure the API does not have (no received total on the client, history events carry the write time, and transactions cannot be filtered by client; computing it in the browser would take one request per service). It is added as its own pull request before the Clients screen: a field `paidThisMonth` on the contact (per currency, with the base value), computed in the receivables service, with OpenAPI, tests that fail first, a ledger-scoping test, the note in `docs/api-changes.md`, and the matching Android type and contract test (the phone adopts it afterwards). It reaches production with the next server release, which is also how any web change does: that release repeats the scratch restore drill with pg-boss started and records the pg-boss 12.38 and off-site image updates (see PROGRESS). The owner tags releases.

## Not changing

The API apart from the one field, ledger scoping, integer minor-unit money and every amount through the shared money component (privacy mode), idempotency keys, the Radix dialog behaviour and focus handling, the unconfirmed-save recovery, live updates (0044) and the installable app (0041), the accessibility pass (0040: titles, one h1 per page that takes focus after navigation, the live region, the 3:1 field border, axe over every screen), no analytics, logs without amounts, payees or notes, light, dark and system themes. The stack is locked: React 19, Vite, TanStack Router and Query, Tailwind v4 with tokens, shadcn/ui (Radix), Lucide, Recharts, React Hook Form and Zod.

## Specs and names that change on purpose

Each pull request lists the tests it changes and why; accessible names are kept wherever the control still exists. Known changes: the Home figures and the Loans summary wording (home.spec and loans.spec look for a link starting with "Lent out"), the net worth card moving off Accounts (home.spec asserts `.net-worth-card` and `.net-worth-owed` on `/accounts`), the Filters sheet in place of the "Filter entries" disclosure and the "Import and export" disclosure on Transactions (several specs open them; disclosures.spec counts summaries there), Export leaving Settings, the contextual Add button's accessible name on a phone, the category row actions and the service action bar becoming sheets (`category-actions.ts` switches on viewport width), the Status select becoming a Pending switch, and the page-title, breadcrumb and heading text the specs read. The h1 "Home" that sign-in detection waits for, one h1 per page, the document titles ("Page · Ledgerline"), the "Main navigation" and "Mobile navigation" landmarks, the palette named "Go to" and the theme and privacy button names are kept.

## Checks

Each pull request: tests that fail before the change; a deliberate-mutation check on each new rule (a script that copies the file, applies one edit, runs the focused tests and restores; a mutation that is not caught means a missing test); a look in the browser at 320, 390 and desktop widths in light and dark; `pnpm lint` (read the output), `pnpm typecheck`, `pnpm test` and `pnpm e2e` (alone and serially); the existing tests that pin behaviour kept green or changed on purpose and said so; then the owner's browser check and the merge on the owner's word. A pull request with an API change also regenerates `docs/openapi.json` and updates the Android contract test.
